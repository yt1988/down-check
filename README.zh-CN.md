# Down Check 挂了吗？

[English](README.md) · **简体中文**

ChatGPT、GitHub、Discord、Cloudflare、Netflix、Steam 现在挂了吗？挂了吗盯着 210 个大家在故障时最常搜的服务，
从**东京和上海**两台自己的探针每 10 分钟各测一次。每页先给当前状态，再给 24 小时在线条和最近 7 天的中断。

**线上地址：** https://down.1ms.dog

- **当前状态优先。** 服务页是一条整行的在线 / 部分异常 / 离线 / 无法确认状态带；每个服务在列表里都带自己的图标，
  一屏名字也能一眼认出来。
- **只由我们的探针判定。** 单点探测失败不会被写成「挂了」：403、429 或验证页记为**无法确认**；数据超过
  20 分钟（漏两轮）记为**无法判断**。服务方自己的状态页只是页面底部的一个参考链接，不参与判定。
- **10 种语言**：English、简体中文、繁體中文、日本語、한국어、Español、Français、Deutsch、Português、Русский。
- **全部服务、全部语言**：`/`、`/<分类>/`、`/<分类>/<服务>/`。

## 怎么判定

| 状态 | 含义 |
|---|---|
| 在线 | 东京和/或上海的探针有回应。 |
| 已恢复 | 现在有回应，但最近 24 小时内有过中断。 |
| 部分异常 | 一个地点有回应，另一个没有。 |
| 无法确认 | 所有回应都是 403/429 或验证页，判断不了。 |
| 离线 | 两个地点现在都没有回应，持续不到一天。 |
| 离线多日 | 超过一天没有回应：更可能是我们的检查出了问题。 |
| 数据过期 / 没有数据 | 数据超过 20 分钟，或者根本没有数据。灰色，不是红色。 |

## 本地运行

```bash
npm ci
npm run build                        # src/ + static/ → public/（不提交，约 2,320 页）
npm run dev                          # build 后开 http://localhost:8791/
npm test                             # build，再跑判定、文案、数据和页面测试
```

要看真实探测数据，先编译并跑一轮探测器（Go 1.22+）：

```bash
cd probe && go build -o ../../down-probe . && cd ..
./down-probe --out probe/out --services probe/services.json --from "Tokyo, JP"
npm run dev
```

`npm run dev` 会读 `probe/out/latest.json`（东京）和 `probe/out/sh/latest.json`（上海，可选）。没有探测文件时
页面显示「没有数据」，这是正确的降级状态，不是报错。本地做设计时，`scripts/dev.mjs` 会用现有小时级基线的
真实历史补齐 24 小时条的前半段；线上不这么做，跑满一天后就是探针自己的 10 分钟一格。

## 部署

Worker 只做两件事：提供静态页面，以及用一个 `/api/status.json` 合并两份探测文件、裁成页面需要的字段、缓存
60 秒，并保留最近一份好数据一周（标记为 `stale`）。没有 cron，也没有 KV：判定只用两台探针写下的东西。

- `public/` 不提交，Workers Builds 跑 `npm ci && npm test` 再 `npx wrangler deploy`；test 会先 build。
- 不绑自定义域：在 1ms.dog 上由 shell 把域名路由到这个 Worker。
- 自己部署时，把自己的域名绑上，并用 Worker 变量 `PROBE_TOKYO_URL` / `PROBE_SHANGHAI_URL` 指向自己的探针输出；
  默认值是 1ms.dog 的数据主机。

## 数据

`probe/latest.json`（每台机器一份）：`at`、`every`、`from`、`complete`，以及每个服务的 `ok`、`unknown`、`ms`、
`http`、`err`、`t`（这个服务自己的测量时间）、`h`（10 分钟一格的历史）、`up24`、`up7`、`out`。Worker 只保留
已发布的服务和最近 144 格（`h24`）之后才发给浏览器。不收集访客信息：页面只读一个同源 JSON，不设 cookie。

## 目录

```
src/services.mjs        210 个服务和 21 个分类（由 data/ 生成）
src/model.mjs           判定、新鲜度和错误映射（页面和测试共用）
src/status-sources.mjs  各服务自己的状态页（只作链接）
src/data.mjs            Worker 从探测文件里保留什么
src/worker.js           /api/status.json
src/app.js              用 JSON 填充页面
scripts/gen-services.mjs  data/baseline.json + data/unlock.json → src/services.mjs + probe/services.json
scripts/build.mjs       2,320 个静态页面、sitemap、robots、llms.txt、_headers
scripts/icons.mjs       构建期抓一次各服务图标，存到 static/icons/
scripts/assets.mjs      每种语言一张链接预览图
probe/                  10 分钟探测器（Go）、systemd unit 和实测成本
static/assets/share/    公共分享组件，从 shell 原样复制（不要在这里改）
```

服务图标在构建期抓一次，提交在 `static/icons/<id>.png`；页面从本站加载，访客不会为此请求任何第三方。没有图标
的服务用两个字母的缩写兜底。分享弹窗同样是 shell 的 `assets/share/` 原样复制，只在点击分享时加载（`?v=10`）；
链接打开的是实时页面，卡片画的是分享时的状态和检测日期。
